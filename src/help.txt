DATAMODDER FILE TOOLS
=====================
A Notepad++ plugin for tidying, validating and converting text data formats:
YAML, JSON and CSV, plus Parquet via DuckDB. 64-bit Notepad++ only.

The menu is grouped: Reindent / tidy on top, then the YAML, JSON, CSV and
Parquet submenus, then Format on Save and Settings / About / Help. Each format
submenu carries the full set of conversions *from* that format, so every
format can reach every other:

           to ->  YAML     JSON     CSV      Parquet
  from YAML        -        yes      yes      yes (file)
  from JSON        yes      -        yes      yes (file)
  from CSV         yes      yes      -        yes (file)
  from Parquet     yes      yes      yes      -
                 (preview) (preview)(preview)

Every command runs on the selection if there is one, otherwise on the whole
document. (The Parquet commands always use the whole file.)


REINDENT / TIDY   (Ctrl+Alt+Y)          YAML, comments preserved
------------------------------
Normalises a block-style YAML document:

  - leading tabs expanded to spaces
  - every nesting level re-emitted at a consistent indent step (default 2)
  - trailing whitespace removed
  - runs of blank lines capped (default: 1)
  - a single trailing newline
  - nesting reset at document markers (--- and ...)

Left untouched, never rewritten: the body of a block scalar ( key: | / > ),
lines inside an unclosed flow collection ( { } / [ ] ), and the text of
comments and quoted scalars.


YAML SUBMENU                            data-only (libyaml)
------------
Parsed with libyaml, so comments and layout are not preserved.

  Validate         first syntax error as "regel R, kolom K: ...", or "Geldige YAML."
  YAML -> JSON     pretty JSON (2-space). Multiple documents -> a JSON array.
                   Anchors/aliases are not supported yet.
  YAML -> CSV      via JSON (expects a sequence of mappings)
  YAML -> Parquet  via JSON; see PARQUET below


JSON TOOLS                              data-only (libyaml)
----------
  Pretty-print  re-emit with the indent set in Settings (default 2 spaces);
                also sorts keys if that's turned on in Settings
  Minify        re-emit compact, one line
  Sort keys     pretty (Settings indent), object keys sorted A->Z recursively
                (array order kept) -- always sorts, regardless of the Settings default

Because the engine is a YAML parser, mildly non-standard JSON (a trailing
comma, unquoted keys) is accepted and cleaned up rather than rejected.


JSON: ESCAPE / UNESCAPE STRING          pure text, no parsing
-----------------------------
  Escape as string   wraps the selection as a JSON string literal ("...\n...")
  Unescape string    turns a "..." literal back into raw text


CSV TOOLS                              pure text (RFC-4180-ish)
---------
Delimiter is sniffed from the first line ( , ; tab | ). Quoted fields, ""
escapes and newlines inside quotes are handled. CR/LF style is preserved.

  Align columns    pad every field so columns line up (a *view* — the padding
                   becomes real data on save, so run Compact first). Quotes
                   values per the Settings CSV quote mode (only when needed,
                   or always).
  Compact          undo Align: trim field padding, minimal quoting
  To comma / To semicolon delimiter
  Sort by column at cursor   stable sort of the data rows by the field the
                             caret is in; header row kept on top; numeric when
                             the whole column is numbers
  Transpose        swap rows and columns
  Add quotes       quote every field, even where the delimiter/quote/newline
                   in the value doesn't require it
  Remove quotes    strip quotes wherever they're not required
  CSV -> JSON      first row = keys, the rest -> an array of objects
  CSV -> YAML      via JSON
  CSV -> Parquet   see PARQUET below

(The JSON submenu has the mirror image: JSON -> YAML / CSV / Parquet, plus
pretty-print / minify / sort keys / escape / unescape.)


PARQUET                                needs duckdb.exe
-------
duckdb.exe must be on your PATH or sitting next to the plugin DLL
( plugins\FileTools\duckdb.exe ), unless you point Settings -> Parquet at a
specific duckdb.exe. Download: https://duckdb.org/

  Parquet -> CSV / JSON / YAML  (preview)
        open a saved .parquet file, then run this; the first 100 000 rows are
        dumped into a NEW tab. Read-only - the .parquet file is never touched.
        (YAML goes through JSON.)

  CSV / JSON / YAML -> Parquet  (file)
        from a saved .csv / .json / .yaml (or .yml) document, write
        <name>.parquet next to it. Unsaved edits are included. YAML is
        converted to JSON first.

Under the hood: read_parquet / read_csv_auto / read_json_auto and
COPY ... TO ... (FORMAT PARQUET).


FORMAT ON SAVE
--------------
"Format on Save: On" runs Reindent / tidy on every save. "Off" disables it.
Persisted across restarts (also settable from Settings -> Behavior).


SETTINGS
========
  YAML       indent step, tab width, max. consecutive blank lines, strip
             trailing whitespace, ensure a final newline
  JSON       pretty-print indent (2 or 4 spaces), sort keys by default
  CSV        quote mode for Align columns: only when needed, or always
  Parquet    override the duckdb.exe location
  Behavior   Format on Save, plus save/load/export/import named profiles
             (JSON files) -- same mechanism as the SQL Formatter plugin

Settings persist in %APPDATA%\Notepad++\plugins\config\FileTools.ini;
profiles are separate .json files under ...\config\FileTools_profiles\.


NOT YET IMPLEMENTED
-------------------
